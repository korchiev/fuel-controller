# fuel-controller

Учебный контроллер АЗС. Протокол в этом репозитории выдуман для уроков. Это не Tatsuno SS-LAN, и эти байты нельзя отправлять на настоящую колонку.

## Кадр

Шесть байт:

```
START  ADDRESS  COMMAND  DATA  CHECKSUM  END
0x02   pump     cmd      byte  sum       0x03
```

`CHECKSUM = (ADDRESS + COMMAND + DATA) & 0xFF`

Команды учебного протокола:

| Команда | Байт | DATA |
| --- | --- | --- |
| GET_STATUS | `0x10` | `0` |
| AUTHORIZE | `0x20` | литры, 0..255 |
| STOP | `0x30` | `0` |
| START_FUELING | `0x40` | `0` |
| RESET | `0x50` | `0` |
| GET_TRANSACTION | `0x60` | `0` |

Ответ колонки — такой же кадр. `COMMAND` равен `ACK` (`0x06`) или `NAK` (`0x15`). Для всех команд, кроме `GET_TRANSACTION`, `DATA` — текущее состояние: `IDLE=0`, `AUTHORIZED=1`, `FUELING=2`, `FINISHED=3`.

Ответ на `GET_TRANSACTION` кладёт в `DATA` отпущенные целые литры, от 0 до 255. Дробные литры и сумма денег в этот байт не помещаются. Сумму симулятор печатает у себя: литры, умноженные на цену.

Чужой адрес колонка игнорирует и молчит. Битый кадр со своим адресом получает NAK.

Пример из урока, «разрешить колонку 2 на 50 литров»:

```
02 02 20 32 54 03
```

## Состояния

```
IDLE --AUTHORIZE--> AUTHORIZED --START_FUELING--> FUELING --STOP--> FINISHED --RESET--> IDLE
```

Пока колонка в `FUELING`, симулятор сам прибавляет целые литры. Когда счётчик доходит до пресета, это то же событие, что `reach_preset()`: переход в `FINISHED` без команды контроллера. `STOP` раньше пресета оставляет уже отпущенный объём. `RESET` обнуляет счётчик и оставляет последний пресет.

Команда не из этой таблицы не меняет состояние и получает NAK.

## Слои

Контроллер вызывает `authorize`, `start`, `transaction` и не собирает кадр. Кадр шести байт собирает только `EducationalDriver`. `TatsunoDriver` занимает тот же слот и пока ни одного кадра не отправляет. Под обоими драйверами один и тот же транспорт: байты туда, байты обратно.

## Запуск

```bash
PYTHONPATH=src python examples/virtual_station.py
PYTHONPATH=src python -m pytest
```

`SerialTransport` переносит байты через COM-порт и не разбирает кадр. Лаборатория на двух USB-RS485 описана в [`lab/README.md`](lab/README.md).
